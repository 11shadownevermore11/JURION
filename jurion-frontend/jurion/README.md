# JURION — фронтенд юридического ассистента ПСБ

**JURION — Юридический интеллект нового поколения.** Веб-интерфейс чата, который отвечает по базе нормативных документов и показывает, на каком пункте держится каждый вывод.

Фронтенд реализует контракт `api.md` целиком: диалоги, история с пагинацией, отправка с `Idempotency-Key`, ответы `200`/`202` с опросом `GET /runs/{id}`, повтор неудачной попытки, все семь исходов ответа, просмотр фрагмента и оригинала источника, обработка ошибок из таблицы контракта.

## Запуск одной командой

```bash
docker compose up --build
```

Откройте <http://localhost:8080>. По умолчанию включён демо-режим: бэкенд не нужен, ответы формирует встроенный мок по контракту API на демонстрационных документах. В интерфейсе это отмечено плашкой «Демо-данные».

Подключение реального бэкенда:

```bash
VITE_USE_MOCKS=false API_UPSTREAM=backend:8000 docker compose up --build
```

nginx проксирует `/api/` на `API_UPSTREAM`. Если бэкенд в том же compose-проекте, добавьте его сервис с именем `backend`.

### Локальная разработка

```bash
npm ci
npm run dev          # http://localhost:5173, моки включены
```

Для работы с бэкендом создайте `.env` по образцу `.env.example` и укажите `VITE_USE_MOCKS=false` и `VITE_API_PROXY_TARGET`.

| Переменная | Где | По умолчанию | Назначение |
| --- | --- | --- | --- |
| `VITE_USE_MOCKS` | сборка | `true` | `true` — встроенные моки, `false` — реальный API |
| `VITE_API_PROXY_TARGET` | `npm run dev` | `http://localhost:8000` | Куда dev-сервер проксирует `/api` |
| `API_UPSTREAM` | контейнер | `backend:8000` | Куда nginx проксирует `/api` |
| `FRONTEND_PORT` | compose | `8080` | Порт на хосте |

Секреты фронтенду не нужны: ключи модели хранит только бэкенд.

## Режимы

- **Полный экран** — `#/`: список диалогов, чат, панель источника.
- **Виджет** — `#/widget`: JURION как боковое окно внутри рабочей системы юриста (на примере карточки договора в СЭД). Кнопка «Спросить JURION» на карточке подставляет контекст договора в вопрос. Из виджета диалог разворачивается на весь экран без потери истории.

## Что отличает интерфейс

1. **Доказательный ответ.** Выводы (`claims`) подчёркнуты прямо в тексте ответа, рядом — номера оснований. Наведение на вывод подсвечивает его основания, клик открывает пункт документа.
2. **Независимая сверка цитат.** Каждая цитата автоматически сверяется с текстом фрагмента, который сервер отдаёт по `chunk_id`. Если модель исказила формулировку, пользователь увидит расхождение до того, как опереться на вывод.
3. **Оригинал с подсветкой.** Панель источника показывает фрагмент с выделенной цитатой и документ целиком с номерами строк и диапазоном `line_start`–`line_end`. Оригинал можно скачать.
4. **Редакция на дату события.** Выбор даты передаётся в `as_of_date`; у реплики видно, по какой редакции дан ответ.
5. **Честные исходы.** Семь исходов отображаются по-разному: частичный ответ с блоком «Чего не хватает», уточняющий вопрос с ответом в том же чате, исправление ошибочной предпосылки, обоснованный отказ.
6. **Справка для руководителя.** Ответ с основаниями печатается или сохраняется в PDF как оформленная справка; можно скопировать в письмо с номерами ссылок.
7. **Надёжная отправка.** Сетевые повторы с тем же ключом, восстановление ожидания после перезагрузки страницы через `latest_run_id`, кнопка повтора для `retryable`-ошибок.

Оформление в фирменном стиле ПСБ из материалов кейса: тёмно-синяя «обложка», оранжевый и фиолетовый цвета знака, анимированная волна-аврора, логотип ПСБ (перенесён в вектор из PDF кейса) и 3D-иллюстрации ПСБ из кейса (`src/assets/brand`).

Также: светлая и тёмная темы, горячие клавиши (`Ctrl K`, `/`, `Esc`, `?`), адаптивная вёрстка до 360 px, шрифты встроены в сборку (без внешних CDN).

## Проверка основного сценария

1. Откройте приложение и нажмите пример «Ответ со ссылкой на пункт».
2. Дождитесь ответа: появится статус «Ответ подтверждён», основания и строка «Все цитаты дословно найдены в источниках».
3. Нажмите на номер основания — справа откроется пункт договора; вкладка «Документ целиком» покажет оригинал с подсвеченной строкой.

Сценарии из раздела «Что покрыть моками» в `api.md`:

| Сценарий | Как проверить в демо-режиме |
| --- | --- |
| Ответ с цитатой и источником | Пример «Ответ со ссылкой на пункт» |
| `202` и опрос `running` → `completed` | Любой вопрос, кроме вне тематики, отвечает через `202` |
| `needs_clarification` и следующая реплика | Пример «Уточняющий вопрос», затем ответ «ООО «Северный Склад»» |
| `partially_answered` / `insufficient_evidence` | Пример «Честно о том, чего нет в базе»; вопрос о старой редакции закона |
| Технический сбой и повтор | Добавьте `#сбой` в вопрос или выберите «Сымитировать сбой» в меню демо-режима |
| Перезагрузка во время ожидания | Отправьте вопрос и обновите страницу до ответа |

Ещё: `#таймаут` в тексте даёт `504 ANSWER_TIMEOUT`; вопросы «вне тематики» и попытки сменить инструкции — `out_of_scope` и `disallowed`.

## Архитектура

```
src/
  api/          типы и клиент по контракту api.md
  mocks/        мок-сервер (перехват fetch для /api/v1) и демо-база знаний
  hooks/        useChat — отправка, опрос, повтор; useConversations; сверка цитат
  lib/          форматирование, сверка цитат, сегментация ответа, справка
  state/        контекст приложения: сессия, маршрут, тема, источник
  components/   brand, layout, chat, sources, widget, ui
  styles/       токены дизайн-системы и стили по областям
```

Мок-сервер подменяет `fetch` только для `/api/v1`, поэтому клиентский код одинаков для демо и реального бэкенда. Состояние мока хранится в `localStorage`; очистить его можно в меню демо-режима.

Стек: React 19, TypeScript 5.9, Vite 7, Lucide Icons, CSS с токенами дизайн-системы. Зависимости фронтенда — npm-пакеты с зафиксированными версиями в `package-lock.json`; Python-зависимости из `requirements.txt` фронтенд не использует и не расширяет.

## Известные ограничения

- В демо-режиме документы базы знаний выдуманы и служат только для показа интерфейса.
- Дата редакции, выбранная при отправке, не возвращается в истории по контракту, поэтому интерфейс хранит её локально в браузере.
- Число документов в блоке «Основания» определяется по подписи цитаты (`label`) до первой запятой.
- Справка открывается через системный диалог печати браузера.
